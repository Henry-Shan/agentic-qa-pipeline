# QA Pipeline — design spec

Date: 2026-07-30 · Status: approved by Haotian (design walked through interactively; prototype at
claude.ai/code/artifact/92e439eb-20d9-4a04-ac03-e77b5f614fea)

## Problem

Testers report the host app bugs/feature requests through Notion/Figma. Reports are hard to organize,
hard to hand to Claude with enough context, and there is no loop for testers to see or verify the
fix. We want: file → autofix → preview → verify, all in the browser.

## Decisions (locked with the user)

| Decision | Choice |
|---|---|
| Testers | Remote team over the internet |
| Capture | Widget embedded in the host app's web app, internal testers only |
| Dispatch | **Autofire on submit**; everyone is admin; testers see results themselves |
| Repo | Separate repo `qa-pipeline` (this one). Widget still ships from the host app's app |
| Database | Reuse prod Supabase project (`YOUR-PROJECT-REF`), `qa_`-prefixed tables in `public` + RLS ($0; a second project costs $10/mo). Only additive DDL. Testers log in with existing the host app accounts, gated by `qa_allowed_emails` |
| Previews | Worktree dev servers on the Mac, tunneled via cloudflared to `preview-<run>.qa.example.com`, behind Cloudflare Access (same allowlist) |
| Runner | Dedicated clone `~/qa-pipeline-runner/the host app` — autofired runs never touch `~/the host app` |
| Merges | Always human. Pipeline stops at PR-ready + tester-verified |

## Architecture

Three deployables in this repo + one small the host app branch:

1. **Site** (`apps/site`) — Next.js on Vercel at qa.example.com. Supabase auth (the host app creds +
   allowlist), board (accumulated, filterable list), task page (log · result · steer), realtime.
   Serves `public/widget.js`. API: `POST /api/ingest` (widget, token + CORS).
2. **Widget** (`packages/widget`) — dependency-free TS IIFE, Shadow-DOM UI, bundled to
   `apps/site/public/widget.js`. From page load it records rolling buffers: console
   errors/warnings, network calls (method/url/status + error bodies, auth headers scrubbed),
   click trail, route changes. Flow: fab → "Report an issue" → element picker (reads
   `data-sentry-component`/`data-sentry-source-file` when present; selector/testid/text always) →
   screenshot with element marked → one-sentence description → POST ingest.
3. **Worker** (`worker`) — daemon on the Mac. Claims queued reports (skip-locked), builds a task
   envelope (JSON + local screenshot files), dispatches headless
   `claude -p /ship-task` (the host app-scoped skill) with the manager-mode relay preamble, and runs a
   **localhost shim** implementing ship-task's existing callback contract
   (`/api/runinfo`, `/api/featuretest`, `/api/ask`, `/api/answer`, `/api/progress`) translated to
   Supabase writes. Also: steer/stop (SIGINT + `claude --resume` same session), rework on
   "still broken", preview servers per worktree (port-scanned, prod API), cloudflared ingress,
   learning notes per area after each run.
4. **the host app branch** `feature/qa-widget` (built last, never pushed without explicit OK):
   conditional `<Script src="https://qa.example.com/widget.js">` for allowlisted users, plus
   `swc-plugin-component-annotate` in the Turbopack config — *progressive enhancement*: verified in
   a real build; if the plugin fails under Turbopack, ship without it (widget degrades to
   selector/testid/text, which is sufficient).

## Grounding (the key requirement)

The widget's component/file is the **entry point, never the assumed bug location**. The dispatch
prompt requires, before any edit:

- Read the screenshot(s) as images; confirm they match the report.
- Traverse the vertical slice (component → hook/store → shared-core API client → Go handler → DB)
  using `graphify-out/graph.json`, the `project memory` MCP (`search_memory`), and
  `qa_area_notes` from past runs (injected into the envelope).
- Reproduce at the API, not the UI (ship-task's existing rule); the recorded network buffer
  usually contains the failing request to replay.
- Server-side evidence: the worker attaches recent Go/Cloudflare log lines matching the report's
  time window when available.
- ship-task's risk floor is unchanged: traces crossing auth/migrations/tenancy force Tier 2.

After each run the worker distills what was learned into `qa_area_notes(area, note)` so later runs
in the same area start smarter (project memory MCP is read-only from our side).

## Lifecycle

`queued → running (grounding/testing/implementing/verifying) → pr_ready → preview → verified → shipped`
Deviations: `rework` (steer/“still broken” → resume same session, same branch), `blocked`
(ship-task STOP or question → needs a human), `stopped` (■ Stop), `failed`, `cancelled`.
Steer box works at any time: mid-run = interrupt + resume-with-note; after = rework resume.
Merge detection (poll `gh pr view`) → `shipped` → preview + worktree teardown.

## Non-goals (v1)

Mobile app reports; rrweb full session replay; auto-merge; multi-repo support; public sign-up.

## Risks & mitigations

- **Turbopack + SWC annotation plugin unproven** → progressive enhancement, verified last.
- **Autofire cost** → concurrency cap (2), duplicate flag against past reports before dispatch,
  per-day run budget in worker config.
- **Runner clone main-checkout mutation** (setup-worktree.sh pulls base in the checkout) →
  dedicated clone + worker serializes dispatches with a lock.
- **Preview exposure** → Cloudflare Access in front of `preview-*` hostnames; NO_TUNNEL localhost
  mode until Access is configured.
- **Secrets** → widget scrubs Authorization/cookie headers and token-shaped strings before upload;
  service-role key lives only in Vercel env + worker .env (never in git).
